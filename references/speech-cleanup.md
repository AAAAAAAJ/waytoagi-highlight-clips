# 口癖与冗余表达精剪

用户要求去口癖、删废话、压缩重复说明或让口播更紧凑时，应用本流程。制作高光时默认做一轮自然精剪；用户要求保留完整问答、原始实验或原话记录时按其范围保留。目标是每段都有信息或观看价值，片长由内容决定。

## 先判断能否删除

结合前后句、语气和画面，标出最小可删区间。词表仅用于找候选，不能全局搜索替换后直接裁音。

| 候选 | 通常可删 | 应保留 |
|---|---|---|
| 填充音与口癖 | 无语义的“呃、嗯、那个、就是说” | 回答中的“嗯”、指向具体对象的“那个” |
| 连接词 | 连续堆叠、没有连接作用的“然后、其实、就是” | 步骤先后、事实修正、解释定义或强调所需的连接词 |
| 重复起句 | “我我我”“这个这个”等失败起句 | 有节奏或情绪作用的重复、段子的铺垫与回环 |
| 自我修正 | 可以独立去掉的口误和未完成起句 | 完整的最终更正、改变结论的否定和范围限定 |
| 同义复述 | 连续几句表达同一件事，后句没有新条件或例子 | 补充操作细节、反例、输入条件或使用边界的句子 |
| 找窗口与等待 | 调整投屏、闲聊、无关停顿、没有信息变化的加载 | 关键鼠标动作、结果出现、反应时间、原始音效和有效留白 |

“不是、不、仅、可能、仍然”等词，数量、单位、工具版本和条件都可能改变结论。删除前后对照完整命题，确认主体、因果、时态、数量和限制保持。比如“目前还不能直接用”不能压缩成“可以直接用”。

删去错误起句后，最终更正应能独立理解；否则保留修正语境。问答不能因删除问句而让答句失去指代。合成口播、补词或整句改写需要另行处理，原声精剪只使用确实说过且语义连贯的片段。

## 编辑顺序

1. 先收紧句段：删无关铺垫和同义复述，保留一个完整的说明及其证据。原话预告与正文有意重复时，按具体出现位置决定去留。
2. 再清理句内：去填充音、重复词、卡顿起句。短到没有自然剪口时，优先保留口癖，或选择另一处完整表达。
3. 最后处理空白：结合画面和音轨收紧停顿，不按统一静音时长一刀切。声音演示、点击反馈和完成状态的停留可以承担内容。

每个删除决定记录：片内起止、类别、原话、删除理由、前后衔接的保留词。对句级冗余另写“保留哪一句、为什么已经说清”。这些由助手完成复核，不要求用户逐条批准。

## 原音与剪点

- 复用逐字稿；词级 ASR 用来找候选和定位。听辨不清或缺少可靠时间码时，先核对短窗，不能按文本字数估算词在声音中的位置。
- 对候选保留前后声音余量，检查最后一个保留音节、呼吸、吞音与串音。先确定真实边界，再对齐项目帧网格。
- 无法隔开口癖与相邻词时，保留这处表达，或换一个自然句界。现有渲染器的 5 ms 淡入淡出只能缓和接缝，不能恢复被截掉的音节。
- 精剪必须改变 `keep` 并重新渲染声音和画面。仅删除字幕中的口头词无法证明音轨已清理。整体倍速也不能替代冗余片段删除。

## 应用删除计划

`scripts/refine_speech.py` 把已复核的删除决定应用到项目时间轴；它不自动识别口癖、不判断语义，也不直接运行视频渲染。

删除计划使用**本轮精剪前的成片时间**：已经按原 `keep` 顺序拼接，但还没有应用本轮删除。这样可以只删除正文中的一次重复，保留相同源句在开头的另一次出现。

```json
{
  "schema_version": 1,
  "timebase": "output",
  "clips": [{
    "id": "01",
    "cuts": [{
      "start": 0.8,
      "end": 1.2,
      "kind": "filler",
      "text": "嗯",
      "reason": "独立填充音，前后两个保留词能自然衔接"
    }],
    "captions": [
      {"start": 0, "end": 0.8, "text": "先打开模型"},
      {"start": 1.2, "end": 3, "text": "再调整镜头"},
      {"start": 3, "end": 8, "text": "查看最后的渲染结果"}
    ]
  }]
}
```

以上时间与原话均为结构示例，必须替换为本次素材。类别可用 `filler`、`repetition`、`restart`、`redundancy`、`waiting`。删除区间须为正、互不重叠、处于本条时长内，端点位于 `1/fps` 秒网格。

`captions` 可省略，省略时从项目现有字幕映射。提供时，它是本条的**完整替换字幕列表**，仍以精剪前成片计时，只写保留的原话。完全处于删除区间内的字幕会一并删除；部分跨剪口的字幕会报错，须根据保留词拆分。不能把含被删词的整句字幕直接压缩到剩余时长。

```bash
python3 scripts/refine_speech.py \
  --project projects/demo/project.json \
  --edits projects/demo/speech-edits.json \
  --out projects/demo-clean/project.json

python3 scripts/render_clips.py --project projects/demo-clean/project.json --validate-only
python3 scripts/render_clips.py --project projects/demo-clean/project.json --clip 01 --sample 8
python3 scripts/render_clips.py --project projects/demo-clean/project.json
python3 scripts/verify_media.py projects/demo-clean/output --report-dir projects/demo-clean/work/verify
python3 scripts/package_delivery.py --project projects/demo-clean/project.json
```

新项目默认使用其所在目录下的 `output/` 和 `work/`；可通过 `--output-dir`、`--work-dir` 指定。脚本保留原项目，拒绝复用旧输出目录；每次修订使用新目录，避免覆盖已有项目、报告或成片。源文件、字体与 Logo 的相对路径会解析后保留正确指向。详细边界以 `--help` 和脚本校验信息为准。

`keep`、逐段裁切、字幕、补充画面、来源标签、封面取帧和开头标题时长一起调整。连续补充画面被切开时，其源起点也相应改变；冻结画面保持原源帧。原封面时间被删除时，改用下一个保留帧，末尾则取前一个，并在报告中说明。

同目录的 `speech-edit-report.json` 记录前后时长、删除内容与理由、原片来源区间、新剪口和复核事项。报告保留在本次任务目录，按交付需要附摘要。源窗时间、旧成片时间和新成片时间不可混用。

## 剪后复核

先连读清理前后的文本，确认信息完整；再回到原音和画面检查接缝。字幕与旁白都不能遗留被删半句、悬空指代或重复起句。

- 检查每个新剪口前后约 0.3—0.5 秒，并连看前后整句：词尾完整、衔接自然、语气与主张一致。
- 删除解说时，如果唯一一次结果或操作恰好在这段出现，保留该画面或重新安排同次演示的补充画面；时间映射只能保证同步，不能判断画面证据是否丢失。
- 字幕、来源标签与补画面须按新时间检查；封面仍须代表结果，不能直接接受自动改选帧。
- 开头区间发生删除后，重新检查前 3 秒能否讲清“这是什么、能做什么或在讲什么”，保留必要介绍；标题剩余时长不足时重新设计，不能只让它匆忙闪过。
- 修改 `keep` 后重新测量响度并渲染受影响条目，核对实际缩短秒数、总时长、SRT、素材包和远端版本。

实际完成了听辨才写“已试听”。工具仅支持 ASR、波形或技术检查时，如实记录范围，对无法确认的剪点保留原音。原声真实性和完整表达优先于凑删减比例。
